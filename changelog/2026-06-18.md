# Release — 2026-06-18 (pending)

_Changes since the previous release (commit `4d74ee6`)._

## Added
- **New Task — scan to link asset (iOS/Android):** Creating a task on mobile now
  opens the camera to scan the asset's QR instead of searching a list. The
  scanned asset is validated (must exist and have an asset assigned) before it's
  linked; web still uses text search.
- **New Asset — address autocomplete:** Location fields now show Google Places
  address suggestions as you type (pick one to fill the field).
- **Swap QR — unified search:** A single "Search for an asset" box that matches
  on name, type, model, serial, asset ID, or assignee — shown above
  "Find by Asset ID" — replacing the separate Model / Type / Assigned fields.
- **End of Life — restore:** Admins now get a **"Bring back in service"** action
  when scanning an End-of-Life asset.

## Changed
- **"Needs repair" now opens the repair form instead of silently flagging:** On the
  asset actions (scan) screen, tapping **Needs repair** on an in-service asset now
  opens the **task form prefilled with that asset + the Repair category**, so the fault
  is captured (title, detail, priority). Submitting creates the repair task, which
  raises the Needs-repair flag server-side — previously the button set the flag with no
  form. (`CreateTaskModal` gained a `prefill` prop.)
- **Bulk bar — Sign off repair/maintenance for an already-flagged asset:** In the
  web multi-select bar, when **exactly one** asset is selected and it's already
  **Needs repair** / **Maintenance due**, the *Needs Repair* / *Maintenance Due*
  set-flag button becomes **Sign off repair** / **Sign off maintenance**. Clicking it
  opens that asset's scan screen with the sign-off task **auto-opened**; closing it
  out logs the work, clears the flag, and leaves the user on the scan menu. With
  several same-status assets selected the buttons keep their bulk set-flag behaviour;
  when the selection has **mixed statuses** the Needs Repair / Maintenance Due buttons
  are **hidden** (bulk-setting one flag across differing statuses is ambiguous).
  (Deep-link: `/check-in/[id]?signoff=repair|maintenance`.)
- **Asset-type fields — "Vehicle Accessories" renamed "Accessories":** the built-in
  extra-field template now reads **Accessories** (the underlying `vehicle_accessories`
  key is unchanged, so existing values are unaffected).
- **Any task now flags the asset Maintenance Due (Repair is the exception):**
  Creating a task against an asset raises **Maintenance Due** for every category —
  Maintenance, Certificate, Inspection, Other — so a pending job always shows on the
  asset's status. A **Repair** task still raises **Needs Repair** instead (repair
  logged via scan is the only exception). Completing the task clears whichever flag it
  raised, and the Tasks feed suppresses the duplicate flag-derived card so one task
  still shows as one row.
- **Asset detail — work labelled by type, and the tab renamed:** In *Current Work
  Details* the work now carries a **Repair** or **Maintenance** badge; in the work
  history the maintenance heading reads **Maintenance** (was "Service"); and the tab
  itself is renamed **Maintenance/Repair** (empty state "No maintenance/repair record
  yet") since it lists both kinds of work.
- **Manual tasks use the same card + sign-off flow as computed tasks:** Manually
  created tasks now render with the **same `TaskCard`** (status chip, asset status
  badge, priority/category/assignee tags, edit pencil, description) and complete
  through the **same `TaskActionModal`** ("Complete task" — completion note +
  optional photo) as sign-off/date tasks, instead of a separate card + modal. The
  feed gives manual items the linked asset's status for the badge.
- **Unified server-computed task feed (`GET /tasks/feed`):** The Tasks tab is now
  built by a **single backend endpoint** that merges manual tasks + overlay-flag
  tasks + date tasks + pending sign-offs, already filtered by assignment. Replaces
  the old client pipeline (3 fetches + a per-asset N+1 for sign-offs + drift
  between the list and the badge count). `useTasks` just fetches the feed; the
  legacy client-side derivation is disabled. Completion paths are unchanged — they
  optimistically drop the item, then reload the feed to reconcile.
- **Status overhaul (Stages 1–3):**
  - **Labels** renamed to **In service / On hire / Needs repair / Maintenance due /
    End of life** across every badge, filter and dashboard chip.
  - **Data model:** `assets.needs_repair` + `assets.maintenance_due` boolean flags
    and an `app_settings` table added (migration `20260710000000`). Needs Repair and
    Maintenance Due are now overlay **flags** — an asset can have both at once
    alongside a base status (In service / On hire / End of life). Existing
    Repair/Maintenance rows migrated to In service + the matching flag.
  - **Badges** now show the base status plus a Needs-repair / Maintenance-due chip
    when set (`AssetStatusBadges`); **filters and counts** are flag-aware, so the
    Needs-repair / Maintenance-due chips match assets by flag.
  - **Backend:** asset PUT accepts the flags; `/settings` endpoints (admin-editable
    `maintenance_due_lead_days`, default 28); a boot + 6-hourly sweep auto-flags
    Maintenance Due when `next_service_date` enters the lead window.
  - **Manual status control:** the asset Edit screen's Status is now editable — a
    base-status picker (In service / On hire / End of life) plus Needs-repair and
    Maintenance-due toggles — so any user can change an asset's status directly.
  - **Per-asset actions (check-in):** the Maintenance section now adapts to the
    asset — **Repair Required** sets Needs repair; **Schedule Maintenance** opens
    the servicing scheduler; when an asset is **Needs repair** / **Maintenance due**
    the buttons become **Sign off repair** / **Sign off maintenance**, which open
    the **same task sign-off modal used in the Tasks tab** (completion note +
    optional photo, and next-service date for maintenance), close out the linked
    task (logs the work + clears the flag), then return to the scan menu. Signing
    off a repair/service no longer changes the base status.
  - **Bulk menu (web):** added **Needs Repair** and **Maintenance Due** (set flags),
    renamed Log Service → **Log Maintenance**, and merged Report Lost / Report
    Stolen into a single **Report Lost or Stolen** picker.
  - **Admin settings:** new **Settings** screen (`/admin/settings`) to edit the
    Maintenance-due lead time (`maintenance_due_lead_days`), reachable from User
    Management.
  - **Log Maintenance advances the schedule:** the Log Maintenance form now
    captures a **Next service due** date (defaults to +6 months) and writes it when
    clearing Maintenance Due, so the auto-sweep won't immediately re-flag the asset.
  - **Mobile multi-scan:** Report Lost / Report Stolen merged into a single
    **Report Lost or Stolen** action (Lost / Stolen chooser), matching the web
    bulk menu.
- **Asset type editor — field labels & order:** The "Model" system field is now
  labelled **"Model Name"**, and in the Add-extra-fields list **Warranty expiry**
  now sits directly under **Warranty terms** so the two warranty fields are
  grouped together. (Applied to both the New and Edit asset-type screens.)
- **Standardised "Clear all" across web filters:** Activity, Search, and Documents
  filter dialogs now all use the same **"Clear all"** wording and the same
  shown-but-disabled-when-empty behaviour. (Activity gained the button; Search now
  shows it disabled instead of hidden; Documents' "Clear" was renamed to "Clear
  all" and disabled when empty.) Sort dialogs always carry a default, so there's
  nothing to clear there.
- **Quick-action available to all users (web search table):** The per-row ⚡
  quick-action button (opens an asset's actions) is no longer admin-only — every
  web user now gets it. The bulk-select checkbox column stays admin-only.
- **Edit button width (non-admin):** On the asset and asset-type screens, when a
  user only sees the **Edit** action (Copy/Delete are admin-only), the button no
  longer stretches the full bar — it's now a sensibly sized, left-aligned button.
- **Web asset list (master-detail):** In the preview pane you can now click the
  asset's image or title/ID to open the full asset page — you no longer have to
  use the "Open full" button. A "Click to open full details ↗" hint was added.
- **Quick-action buttons (check-in screen):** Colour is now purely positional in
  every scenario (In Service, Placeholder, QR-reserved, awaiting-QR, End of
  Life) — the **left** column is always blue (filled) and the **right** column
  always orange (outlined), regardless of which action lands there.
- **Imported-asset quick actions:** Standardised the button grid — blue actions
  on the left, orange on the right — and "Assign Imported Asset" now stays on
  one line.
- **Places API:** The address-autocomplete endpoint now reports the real Google
  error (e.g. `REQUEST_DENIED`) instead of silently returning no results, so
  misconfiguration is visible.

## Added
- **Repair / Maintenance-due transfer warning:** if a scanned asset still has an
  unresolved **Needs repair** or **Maintenance due** flag (task not signed off),
  the check-in screen alerts **once when the asset is opened**, and again as a
  **confirm** before any transfer (to office / to user / to me) — the user can
  cancel or transfer anyway (the task stays open until signed off). Uses the app's
  in-app `ConfirmModal` (styled, cross-platform), not a browser dialog.

## Fixed
- **Task cards — job-type chip, identical for manual & system tasks:** The top-left
  chip now labels the **job type** — **Maintenance / Repair / Certificate / Hire /
  Other** — so a card reads its purpose at a glance, and it's derived the same way
  whether the task was created manually or by scanning/flagging an asset (so both
  render identically). The redundant blue category tag in the footer was removed
  (the chip carries it now), and **overdue** is shown on the due-date pill itself
  ("Overdue · <date>", red) rather than as a separate chip. Task cards still show the
  linked **asset's status badge** (In service / Needs repair / Maintenance due) as
  the single asset-status indicator. Flag/date/sign-off items carry the asset's
  status + flags.
- **Task visibility & permissions tightened:**
  - **Strict "assigned to me":** non-admins now see only tasks (manual, sign-off,
    and flag/date-derived) for assets/tasks **assigned to them** — unassigned/shared
    tasks are admin-only. The Tasks badge count matches. Admins still see everything.
  - Non-admin task creation now **auto-assigns to the creator** (they can't pick an
    assignee), so their tasks stay visible under the strict rule.
  - **Sign-off ownership enforced server-side:** a non-admin can only sign off a
    Repair/Maintenance/Hire action for an asset **assigned to them** (403 otherwise).
    Manual-task completion already enforced creator/assignee; admins can close any.
  - **Tasks follow the asset on transfer:** transferring an asset to another user
    now reassigns its open manual tasks to that user (or unassigns them on transfer
    to office). Derived tasks already track the asset's owner.
- **Tasks not updated for the new status-flag model:**
  - Creating a manual **Repair/Service/Maintenance/Inspection** task no longer sets
    the legacy `Repair`/`Maintenance` base status — it now raises the matching
    **overlay flag** (`needs_repair` / `maintenance_due`); completing the task
    clears it. (Fixes assets stuck showing the old "Repair" status.)
  - The Tasks tab now **derives a task from the flags** — an asset marked Needs
    repair or Maintenance due (via scan, check-in, bulk, edit, or a created task)
    shows a task; completing it logs the work to Maintenance history and clears
    the flag.
  - Signing off a Repair/Maintenance action now **clears the matching flag**
    instead of only resetting the base status.
- **Log Service / Repair submit did nothing (no maintenance record):** The
  `POST /assets/:id/actions` validator required a full ISO datetime for
  `occurred_at`, but the Log Service / Repair form and the Servicing screen send
  a date-only string (`YYYY-MM-DD`). The request 400'd, and because
  `Alert.alert` is a no-op on the web app, the error was invisible — the form
  didn't close and nothing was recorded. Fixed on both sides: the Log Service /
  Repair form and the Servicing screen now send a full ISO datetime, and the
  validator also tolerates date-only (normalised to midnight UTC). The web form
  now surfaces errors via a real browser alert instead of failing silently.
- **iOS date picker:** Spinner text was washed out / unreadable — now
  high-contrast (forced light theme + explicit text colour).
- **New Asset (scan to select ID):** Form fields appeared ~1 second after
  scanning a QR; they now appear immediately.
- **QR-reserved assets:** The "Add image" button is hidden until a real asset is
  assigned to the QR.
- **Swap via Scan QR:** Scanning an empty / reserved / End-of-Life QR (or the
  same QR) is now blocked with a clear validation message instead of proceeding.
- **End-of-Life screen:** The "Back to Dashboard" button no longer truncates to
  "Back to …".
